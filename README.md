# 🛒 나의 소비패턴 (My Consumption Pattern)

> 사진을 업로드하거나 카메라로 촬영해 장보기 상품과 수량을 기록하는 AI 장바구니 기록 서비스입니다.

사진 속 객체를 YOLO 모델로 탐지하고, 날짜·상품·수량을 표와 CSV로 관리합니다. 현재 버전은 구매 기록을 쌓는 MVP이며, 소비 주기 분석과 냉장고 보관 기간 추적은 향후 개선 목표입니다.

---

## 1. 주제 및 만든 이유

장을 보고 온 뒤 구매한 물품을 가계부나 메모장에 일일이 기록하는 일은 번거롭습니다. 그래서 자주 사는 식재료와 생필품의 구매 내역을 간편하게 남기고 확인할 수 있도록 이 서비스를 기획했습니다.

- **소비 기록 관리**: 사진을 분석해 상품 종류와 수량을 기록합니다.
- **소비 주기 파악 기반 마련**: 누적 구매 기록을 모아 자주 구매하는 상품과 구매 시점을 살펴볼 수 있도록 데이터를 저장합니다.
- **식재료 관리 기반 마련**: 구매 날짜를 기록해 향후 냉장고 보관 기간이나 소비 기한 알림 기능으로 확장할 수 있습니다.

사용자는 상품 사진을 업로드하거나 브라우저 카메라로 촬영합니다. 객체 탐지 결과를 확인한 뒤 상품별 수량을 날짜와 함께 기록하고, 전체 기록을 표로 보거나 CSV로 내려받을 수 있습니다.

> 현재 앱은 브라우저 카메라로 사진을 촬영해 분석합니다. 연속 영상 스트리밍 방식의 실시간 탐지는 포함하지 않았습니다. 소비 주기 계산과 보관 기간 알림도 향후 개선 항목입니다.

---

## 2. 사용 모델 및 라이브러리

### AI 모델

- **Ultralytics YOLO (`yolo26n.pt`)**: 이미지에서 객체를 탐지하고, 클래스별 감지 수량을 집계합니다.
- **모델 교체**: 기본 모델 대신 상품 이미지로 학습한 가중치 파일을 지정해 세부 상품 인식에 활용할 수 있도록 구성했습니다.

기본 모델은 일반적인 객체 클래스에 한정되어 있어 특정 브랜드나 세부 상품명을 정확히 구분하지 못할 수 있습니다. 상품별 인식을 위해서는 해당 상품 이미지와 라벨로 별도 학습한 모델이 필요합니다.

### 기술 스택 및 라이브러리

| 구분 | 라이브러리 | 역할 |
| :--- | :--- | :--- |
| 웹 UI | `Streamlit` | 이미지 업로드, 카메라 촬영, 모델 설정, 데이터 표와 다운로드 버튼 제공 |
| 객체 탐지 | `Ultralytics` | YOLO 모델 로드 및 이미지 객체 탐지 |
| 이미지 처리 | `OpenCV (cv2)`, `Pillow`, `NumPy` | 이미지 색상 형식 변환, 업로드 이미지 처리 및 탐지 결과 표시 |
| 데이터 처리 | `Pandas` | 클래스별 수량 집계, 기록 정렬, CSV 입출력 |
| 시간·경로 관리 | `datetime`, `zoneinfo`, `pathlib` | 한국 시간 기록 및 파일 경로 관리 |

## 3. 어려웠던 점과 해결 방법

### 배포 환경의 시간대 차이와 기록 정렬

**문제:** 로컬 컴퓨터와 배포 서버의 시간대가 달라 기록 시간이 실제 한국 시간과 다르게 보일 수 있었습니다. 또한 문자열 상태의 날짜를 정렬하면 저장 형식이 섞였을 때 순서가 어긋날 수 있습니다.

**해결:**

- `ZoneInfo("Asia/Seoul")`를 이용해 서버 위치와 관계없이 한국 시간으로 기록합니다.
- ISO 8601 형식의 시간값을 저장하고, 정렬할 때 날짜를 실제 날짜·시간 값으로 변환합니다.
- 화면과 다운로드 CSV에는 초까지만 표시해 읽기 쉽게 했습니다.
- 전체 기록은 최신 기록이 위에 오도록 정렬합니다.

### 모델 교체와 반복 로딩

**문제:** 추후 자체 학습 모델을 사용할 때 코드에서 모델 경로를 매번 바꾸는 번거로움을 줄이고 싶었습니다.

**해결:**

- `@st.cache_resource`를 이용해 모델을 캐시합니다.
- 사이드바에서 모델 이름 또는 가중치 경로와 감지 신뢰도를 설정할 수 있도록 했습니다.

## 4. 한계 및 향후 개선 방향

- **기본 모델의 상품 분류 한계:** COCO 사전학습 모델은 `bottle`, `apple`과 같은 일반 클래스 중심입니다. 특정 우유 브랜드나 세부 식품 종류를 구분하지 못할 수 있습니다.
- **커스텀 상품 모델 학습:** 한국 마트 상품과 식재료 사진을 수집해 상품별 클래스를 라벨링하고, 사용자 정의 객체 탐지 모델을 학습할 계획입니다.
- **소비 주기 분석:** 누적 구매 기록을 활용해 상품별 재구매 간격과 소비 패턴을 분석하는 기능을 추가할 수 있습니다.
- **보관 기간 관리:** 구매일을 기준으로 냉장고 보관 기간과 소비 권장 시점을 관리하는 기능을 추가할 수 있습니다.
- **영구 데이터 저장:** 현재 기록은 `result/counts.csv` 파일에 저장됩니다. 호스팅 서비스에서는 파일이 재시작·재배포 후에도 유지되지 않을 수 있으므로, 장기간 운영 시 데이터베이스나 영구 저장소 연결이 필요합니다.

## 5. 프로젝트 구조 및 실행 방법

### 프로젝트 구조

```text
mimini/
├── app.py              # Streamlit 메인 애플리케이션
├── requirements.txt    # Python 라이브러리 목록
├── packages.txt        # 배포에 필요한 시스템 패키지 (필요한 경우)
├── weights/            # 사용자 학습 모델을 둘 수 있는 선택 폴더
│   └── best.pt
└── result/
    └── counts.csv      # 누적 기록 (앱 실행 후 자동 생성)
```

기본 모델 `yolo26n.pt`는 Ultralytics가 모델 이름을 통해 내려받도록 사용할 수 있습니다. 사용자 학습 모델을 쓰려면 가중치 파일을 저장소에 포함하거나 배포 환경에서 접근 가능한 저장 위치를 지정하세요.

### requirements.txt 예시

```text
streamlit
ultralytics
pandas
pillow
opencv-python-headless
numpy
```

### 로컬 실행

```bash
# 1. 저장소 복제
 git clone https://github.com/<사용자명>/<저장소명>.git
 cd <저장소명>

# 2. 패키지 설치
python -m pip install --upgrade pip
pip install -r requirements.txt

# 3. 앱 실행
streamlit run app.py
```

실행 후 터미널에 표시되는 로컬 주소(일반적으로 `http://localhost:8501`)를 브라우저에서 엽니다.

### Streamlit Community Cloud 배포

1. `app.py`와 `requirements.txt`를 GitHub 저장소에 올립니다.
2. Streamlit Community Cloud에서 **Create app**을 선택합니다.
3. GitHub 저장소와 브랜치를 선택하고 앱 파일 경로로 `app.py`를 지정합니다.
4. 배포가 완료되면 제공된 앱 주소로 접속합니다.
5. 앱을 수정한 뒤에는 변경 사항을 GitHub에 커밋하고 푸시해 배포에 반영합니다.

## 6. 기록 데이터

기록은 다음 열로 구성됩니다.

| 날짜 | 상품 | 수량 |
| :--- | :--- | ---: |
| 2026-11-20 15:30:10 | apple | 2 |
| 2026-11-20 15:30:10 | bottle | 1 |

앱에서 전체 기록을 확인하고 CSV로 다운로드하거나, 초기화 버튼으로 기록을 지울 수 있습니다. CSV는 한글 호환을 위해 UTF-8-SIG 인코딩으로 저장됩니다.
