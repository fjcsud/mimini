# 🛒 나의 소비패턴 (My Consumption Pattern)

> **사진 한 장으로 장본 내역과 수량을 자동 기록하고, 나만의 소비 주기와 냉장고 보관 기간을 추적하는 AI 장바구니 기록 서비스**

---

## 1. 주제 및 만든 이유 (기획 배경)

장을 보고 온 뒤 구매한 물품들을 일일이 가계부나 메모장에 적는 과정은 매우 번거롭습니다. 이로 인해 다음과 같은 일상 속 불편함이 반복되었습니다.

* **소비 주기 파악 불가**: 생필품이나 자주 사는 식자재를 어느 정도의 주기로 다 쓰고 재구매하는지 가늠하기 어렵습니다.
* **식재료 방치 및 폐기**: 냉장고에 언제 넣어둔 재료인지 잊어버려 유통기한이 지나 버리게 되는 일이 발생합니다.

**'나의 소비패턴'**은 이러한 문제를 해결하기 위해 탄생했습니다. 장본 물건들을 카메라로 찍거나 사진으로 업로드하기만 하면, 객체 탐지(Object Detection) 모델이 상품과 수량을 자동으로 파악해 날짜와 함께 CSV 데이터로 누적 기록해 줍니다.

---

## 2. 사용 모델 및 라이브러리

### AI Model
* **Ultralytics YOLO (`yolo26n.pt`)**: 빠른 추론 속도와 경량화된 크기를 바탕으로 이미지 내 다수의 상품 객체를 실시간 탐지 및 클래스별 수량 집계에 사용했습니다. *(추후 커스텀 학습된 모델 가중치 경로로 손쉽게 교체 가능하도록 설계)*

### Tech Stack & Libraries

| 구분 | 라이브러리 | 역할 |
| :--- | :--- | :--- |
| **Web UI** | `Streamlit` | 사진 업로드, 웹캠 촬영, 신뢰도(Confidence) 조절 사이드바 및 데이터 테이블 시각화 |
| **Computer Vision** | `OpenCV (cv2)`, `Pillow` | 이미지 포맷 처리 및 바운딩 박스 탐지 결과 렌더링 |
| **Data Processing** | `Pandas`, `NumPy` | 탐지된 객체 수량 집계, 타임스탬프 기반 시간순 정렬, CSV 파일 입출력 및 다운로드 |
| **Time & Path** | `zoneinfo`, `pathlib` | 배포 서버 환경과 무관한 한국 표준시(`Asia/Seoul`) 기록 및 결과 경로 관리 |

## 3. 어려웠던 점과 해결 방법

### 1) 배포 및 모바일 환경에서의 시간대 불일치 및 정렬 순서 꼬임 문제
* **어려웠던 점**: 로컬 PC 환경에서는 정상적으로 시간순 누적 기록이 작동했으나, 웹에 배포한 뒤 모바일(핸드폰) 환경에서 실행하면 서버 시간대 차이(UTC vs KST) 및 기록 병합 과정에서 시간순 정렬이 뒤섞여 최신 기록의 위치가 어긋나는 현상이 발생했습니다.
* **해결 방법**: 
  * `zoneinfo.ZoneInfo("Asia/Seoul")`과 ISO 8601 마이크로초 포맷(`isoformat(timespec="microseconds")`)을 적용해 배포 서버 위치와 관계없이 정확한 한국 시각으로 저장하도록 통일했습니다.
  * 내부 저장 시에는 `pd.to_datetime(..., format="mixed", utc=True)`로 실제 시각 객체를 파싱해 시간순(`ascending=True`, `kind="stable"`)으로 안정적으로 정렬하고, 화면 출력 및 CSV 다운로드 시에는 `history_for_display()` 함수를 거쳐 보기 깔끔한 초 단위(`%Y-%m-%d %H:%M:%S`)로 변환해 제공하도록 개선했습니다.

### 2) 모델 교체 유연성 확보
* **어려웠던 점**: 향후 자체 학습시킨 상품 인식 모델을 적용할 때 코드를 매번 수정해야 하는 번거로움이 있었습니다.
* **해결 방법**: `@st.cache_resource`로 모델 로딩 속도를 최적화하는 한편, 사이드바 UI에서 모델 파일 경로와 감지 신뢰도(Threshold)를 실시간으로 변경할 수 있도록 구현했습니다.

---

## 4. 아쉬운 점 및 향후 개선 방향

* **데이터 클래스 세분화의 한계**: 현재 기본 YOLO 모델이 제공하는 사전 학습 데이터는 일상 사물 위주의 큰 범주(예: `bottle`, `apple` 등)로만 분류되어 있어, 실제 마트에서 판매하는 구체적인 상품명이나 세분화된 식재료(예: 우유 브랜드, 채소 세부 품목 등)까지 구분하는 데 한계가 있었습니다.
* **향후 보완 계획**: 실제 서비스 수준의 본격적인 배포를 위해서는 한국 마트 상품 및 식재료 이미지 데이터셋을 추가로 구축하여 커스텀 파인튜닝(Fine-tuning)을 진행할 계획입니다.

## 5. 프로젝트 구조 및 실행 방법

### 프로젝트 구조
```text
mimini/
├── app.py              # Streamlit 메인 애플리케이션 코드
├── yolo26n.pt          # YOLO 객체 탐지 모델 가중치
├── requirements.txt    # 파이썬 의존성 패키지 목록
├── packages.txt        # 시스템 패키지 목록 (배포용)
└── result/
    └── counts.csv      # 누적 소비패턴 기록 파일 (자동 생성)
```

### 로컬 실행 방법
```bash
# 1. 저장소 클론
git clone https://github.com
cd mimini

# 2. 필수 패키지 설치
pip install -r requirements.txt

# 3. 앱 실행
streamlit run app.py
```
